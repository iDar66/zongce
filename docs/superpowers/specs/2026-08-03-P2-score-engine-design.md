# P2 综测评分引擎设计

日期：2026-08-03

## 目标

在 P1 的活动证明加分预测之上，增加单个学生的综测评分预测：读取上下学期成绩 Excel，汇总 P1 的品德/学业/文体附加 raw，计算基本分、封顶折算分和综测总分，并在输出中明确区分实测与估算数据。

本期不做全班批量计算、排名、奖学金资格判断或 Streamlit UI。P3 的门槛判定保持独立。

## 已确认口径

- 品德基本分：70。
- 文体基本分：60。
- 学业基本分：全年成绩按学分加权平均后乘 0.8。
- 学业附加封顶：20；文体附加封顶：40。
- 当班级最高 raw 超过板块封顶值时：`个人 raw / 班级最高 raw * 封顶值`；不超过封顶值时，个人 raw 直接计入（并以封顶值作安全上限）。
- 无法取得班级最高 raw 时，P2 默认按对应封顶值的 1.25 倍估算，并在结果中标记“估算”。
- 品德附加不做本期封顶折算；各板块分数不强制截断到 100。
- 综测总分：`品德 * 0.20 + 学业 * 0.65 + 文体 * 0.15`。

估算模式下，学业和文体均使用 `class_max_raw = cap * 1.25` 作为折算分母；折算结果限制在 `[0, cap]`，避免个人 raw 超过估算分母导致附加分超过封顶。若用户提供真实班级最高 raw，则对应板块改用实测分母。

## 输入

### 成绩 Excel

P2 CLI 接受重复的 `--grade-file PATH` 参数；本期要求提供上下学期各一份，且两份文件中的 `学年` 相同、`学期` 分别为 1 和 2。成绩表必须包含以下列：

`学年`、`学期`、`课程代码`、`课程名称`、`学分`、`成绩分项`、`成绩`。

`grades.py` 只读取每门课 `成绩分项 == "总评"` 的行，忽略平时、实验、期末等分项。课程成绩和学分必须可解析为有限数值；同一学期同一课程代码不得出现多个总评行。

输出一个不可变的成绩摘要 dataclass，至少包含：课程数量、总学分、学分加权成绩总和、全年加权平均成绩、来源文件和学期信息。

### P1 活动预测

继续复用 P1 的 `Prediction` 列表。每个板块的 raw 是该板块所有 `points` 为数值的预测之和；待确认项目不进入自动 raw 合计，但在评分报告中记录待确认数量和提示。

### 可选班级最高 raw

增加可选的学业、文体班级最高 raw 参数。未提供的学业/文体参数走 1.25 倍封顶值估算；品德不参与本期封顶折算，也不需要班级最高 raw 参数。

## 模块设计

### `zongce/grades.py`

职责：解析成绩 Excel、校验结构、按课程总评汇总全年成绩。该模块不依赖 P1 OCR 或导出模块。

建议契约：

```python
read_grade_files(paths: Sequence[str | Path]) -> GradeSummary
```

### `zongce/score.py`

职责：将 `GradeSummary` 与 `Prediction` 列表组装为评分报告，只实现纯计算，不读写文件。

评分报告需要同时保存：每板块 raw、基本分、附加封顶/折算分、最终板块分、折算分母及其来源（实测/估算）、待确认数量、综测总分。

建议契约：

```python
calculate_score(
    predictions: Sequence[Prediction],
    grades: GradeSummary,
    class_max_raw: Mapping[str, float] | None = None,
) -> ScoreReport
```

### `pipeline.py` 与 `cli.py`

保持现有 P1 调用方式和输出不变。只有传入 `--grade-file` 时才进入 P2 评分，并把 `ScoreReport` 交给导出层。CLI 对成绩文件数量、路径、学期重复/缺失和数值错误给出明确中文错误信息。

### `export.py`

保留原有“综测加分明细”工作表和板块文件复制行为；P2 模式额外增加“综测评分预测”工作表，至少展示：成绩加权平均、三板块 raw、基本分、折算附加、最终板块分、总分、班级最高 raw 来源、待确认提示。

## 数据流

```text
成绩 Excel x2 -> grades.read_grade_files -> GradeSummary
活动目录 -> P1 pipeline -> Prediction 列表
GradeSummary + Prediction 列表 -> score.calculate_score -> ScoreReport
Prediction 列表 + ScoreReport -> export.py -> 原明细页 + 评分预测页 + 板块文件夹
```

## 错误处理

- 成绩文件不存在、无法读取或缺少必需列：P2 直接失败并指出文件和缺少项。
- 上下学期缺失、学年不一致、同课程重复总评：P2 直接失败，不生成误导性的评分页。
- 成绩/学分为非数值或无限值：指出具体课程和来源文件。
- P1 单个证明提取失败：沿用 P1 当前行为，保留待确认预测；只要评分所需成绩有效，仍可输出评分报告，并标出待确认 raw。
- 估算班级最高 raw：评分页必须显示“估算（封顶值 × 1.25）”，不能伪装为实测。

## 测试计划

1. `grades.py`：用临时合成 Excel 验证总评筛选、学分加权、上下学期合并、缺列/重复/非数值报错。
2. `score.py`：验证基本分、无封顶折算、估算分母、实测分母、封顶边界、待确认项目和总分权重。
3. `export.py`：验证 P1 明细页保持不变，P2 评分页字段和估算标记正确。
4. `pipeline.py`/CLI：验证不传成绩参数时 P1 回归行为不变，传入两份成绩表时端到端生成评分页。
5. 完成后重新运行 P1 全量测试，并用用户提供的上下学期成绩表做一次本地端到端核算；成绩文件不复制进仓库或测试 fixture。

## 非目标与后续

- 不在 P2 中实现 P3 奖学金四道门槛、竞赛等级自动认定或全班排名。
- 不联网、不调用云 API、不把成绩或证明材料写入 git。
- 以后拿到全班 raw 时，只需通过可选参数替换估算分母，不改变评分公式。
