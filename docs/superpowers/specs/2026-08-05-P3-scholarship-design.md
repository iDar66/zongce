# P3 专项奖学金（竞赛类）判定 设计

日期：2026-08-05

## 目标

在 P1（活动加分预测）+ P2（综测总分）之上，为单个学生判定可申报的**普通奖学金（学科竞赛获奖类）**，输出每个竞赛的认定级别、4 道硬门槛通过情况、奖金预估与待确认项。第一版以**五一数学建模竞赛**为黄金端到端用例（用户真实材料，且在内置已知库内，零联网即可全自动判定）。

## 范围

- 只做普通奖学金（竞赛类，含数学建模、泰迪杯、蓝桥杯等）。
- 不做论文奖学金、体育类、文艺类（另涉不同认定规则，用户暂无材料）。
- 不做校级优秀学生系列 / 国家奖 / 国家励志（①组 + 国家级，靠班级排名，留后续 P3.x）。
- 不做挑战杯 / 互联网+ / 创青春（走另办法，只在输出里标「另报」）。

## 已确认决策

- **路线 A：分层自动**——内置已知竞赛库（级别+比例查清，零联网即判）+ 未知竞赛联网查官网公示 + OCR 主办方与分类表辅助定级 + 认定文件兜底。
- **联网受限例外**：P3 的「获奖比例」步骤允许联网，仅 fetch 竞赛官网公示 URL，解析公开的获奖/参赛数，**禁止传输任何学生 PII**（姓名/学号/成绩/证明内容）。P1/P2 仍全本地。此为 AGENTS.md 硬约束 #2 的 P3 受限例外，实现时需同步更新 AGENTS.md。
- **分类表是混合结构**：白名单（国A/省A 具体名单）+ 描述性规则（国B/省B/校C 按主办方性质），定级需两种都支持。
- **联网默认关闭**，需 CLI 显式 `--allow-online` 开启；未开启时未知竞赛一律标「待确认（需联网查比例）」，绝不静默联网。

## 数据源

### P1 竞赛获奖证明（自动接）
复用 P1 的 `Prediction` 列表，筛 `panel == "学业"` 且 `mode == Mode.GRADE`（获奖分级型）。每个证明带：文件名、OCR 陈述、识别到的奖项关键词（一等奖/三等奖/冠军…）。

### 分类表（附件1 .xls）
`D:\综测证明材料\附件1.广东技术师范大学学科竞赛分类表（2026） .xls`，Sheet1，91 行 × 4 列（序号/竞赛名称/网址/主办单位），按级别分段：

- **国家级 A 类**（行 3–65，约 60 项白名单）。数模相关：`全国大学生数学建模竞赛`→国A（主办：中国工业与应用数学学会）。
- **国家级 B 类**（行 67–68，描述性）：「除学科竞赛排行榜外，教育部教指委 / 国家一级学会 / 中国科协及其全国学会 / 中国文联及其全国文艺家协会主办」。
- **省级 A 类**（行 69–85，约 16 项白名单）。数模相关：`广东省大学生数学建模竞赛`→省A（主办：中山大学）。
- **省级 B 类**（行 87–88，描述性）：「省级政府部门 / 省级教指委 / 省一级学会组织的全省性竞赛；国家级 A 类省级及赛区竞赛未列入省A 的计入省B」。
- **校级 C 类**（行 89–90，描述性）：「教务处 / 学生处 / 团委组织统筹的校级竞赛，以及国A / 省A 的学校选拔赛」。

`catalog.py` 解析此表为：白名单 dict（竞赛名→级别，含主办方/网址）+ 描述规则（级别→主办方性质条件）。

### 内置已知竞赛库
内置已查清的竞赛：认定级别路径、获奖比例（或「天然过门槛」标志）、官网公示 URL。首条 **五一数模**：江苏省工业与应用数学学会（省一级学会）→ 省B → 「行业协(学)会主办降一级」→ 校C；章程规定一/二/三等奖分别 ≤ 报名队数 5%/15%/25%，合计 ≤ 45% < 50%，**天然过比例门槛**。

### 认定文件（可选，yaml）
用户对库内没有的竞赛补充：组队人数、是否学校统一组织 + 备案、申报时间范围、官网公示 URL、已知参赛总数 / 获奖数。路径由 CLI `--competition-file` 传入。未提供的字段标待确认。

### 联网（受限）
`ratio.py` 在需要比例且 `--allow-online` 时，fetch 用户/库提供的官网公示 URL，解析获奖数与参赛总数算比例。只读公开页面，不提交任何表单 / 学生数据。

## 模块设计

依赖单向：`catalog → level → ratio → scholarship → pipeline → cli / export`。

| 模块 | 职责 | 关键契约 |
|---|---|---|
| `catalog.py` | 解析分类表 .xls → 白名单 + 描述规则 | `load_catalog(path) -> Catalog`；`Catalog.lookup(competition, host) -> LevelHit` |
| `level.py` | 定级引擎：白名单匹配 + 主办方性质描述匹配 + 降一级 | `decide_level(competition, host, catalog, known) -> LevelDecision(level, basis, confidence, note)` |
| `ratio.py` | 获奖比例：已知库 + 联网 fetch + 用户填 | `award_ratio(competition, known, online, url) -> RatioResult(ratio, source, note)` |
| `scholarship.py` | 4 门槛 + 奖金（级别×折算×组队）+ 组装报告 | `evaluate_competition(...) -> ScholarshipItem`；`PRIZE_TABLE`/`LEVEL_SCALE`/`TEAM_FACTOR` |

### 竞赛识别（pipeline 层，把 P1 prediction 解析成竞赛候选）
P1 的「学业-GRADE」证明不直接等于「竞赛身份」。pipeline 先把每个这种证明解析为竞赛候选 `(competition, host, award)`，再喂给定级/比例/门槛：

- **竞赛身份 competition**：已知库关键词匹配（`prediction.file` 文件名 + `prediction.basis` OCR 陈述）→ 命中则取库内身份；未命中取文件名启发式 + 标「待确认身份」。
- **主办方 host**：已知库 > 认定文件 > OCR 陈述启发式提取（低信心）。
- **奖项 award**：复用 P1 GRADE 模式已识别的奖项关键词，映射到 {特等 / 一等 / 二等 / 三等 / 其他}。

识别失败的证明仍进报告，标「待确认」，不丢弃。

### 定级流程（level.py）
1. 已知库命中 → 直接用库里的级别路径（含降级）。
2. 否则白名单匹配（竞赛名 / 主办方在国A / 省A 名单）→ 对应级。
3. 否则描述性匹配：按主办方性质判 国B / 省B / 校C。
4. 若主办方属「行业协(学)会」且非政府部门直管 → 降一级（影响奖金序列；点名：五一数模、泰迪杯）。
5. 序列：国A > 国B > 省A > 省B > 校C。
歧义（主办方性质不清 / 分类表未覆盖）→ `confidence="低"`、`note` 标「待辅导员认定」。

### 4 道硬门槛（scholarship.py，须同时满足）
1. **主办方资质**：政府部门 / 行业协(学)会；公司企业主办 → 不通过。
2. **获奖比例 ≤ 50%**（不含优秀奖）：`ratio = (特等+一+二+三) / 参赛总数`。
3. **学校相关部门 / 学院统一组织 + 备案**（用户在认定文件确认）。
4. **在申报时间范围内**（用户确认）。
门槛 3、4 缺数据 → 标「待确认」，不强行判不通过。

### 奖金计算（管理办法第 13 条第 2 款）
- 基准（国家级，元/人）：特等 3000 / 一等 2000 / 二等 1500 / 三等 800。
- 级别折算：世界级 ×3，省级 ×0.5，市级 ×0.25。
- 组队系数：2–4 人队总额 = 个人额 × (人数+1)/2；5 人及以上 = 个人额 ×3。
- 定级流程：先分类表定级 → 「行业协(学)会主办」再降一级。
- **校C 无专项奖金标准**（专项只覆盖国际 / 国 / 省 / 市四级）→ 校C 时奖金标「专项不覆盖，综测加分不受影响」。
- 推算示例：省级三等 3 人队 = 800 × 0.5 × (3+1)/2 = **800 元总额**（人均约 267）。

## 输出

现有 `综测加分明细.xlsx` 新增「专项奖学金预估」sheet，对标用户目标 xlsx 第 3 节：

- 每竞赛一行：竞赛名称 / 认定级别 / 4 门槛逐项（✅ / ❌ / ⚠️待确认）/ 奖金（总额 + 人均）/ 把握度（全门槛过 = 🟢，卡认定 = 🟡，缺数据 = 🔵待确认）/ 待确认项。
- 末尾附：互斥 / 叠加提示（专项可与 ①组、国家奖叠加）、待认定清单。

## 错误处理

- 分类表缺失 / 解析失败：P3 跳过白名单匹配，全部走描述性 + 待认定，不崩。
- 定级歧义：标「待辅导员认定」，仍输出该竞赛行（级别空 / 低信心）。
- 官网 fetch 失败 / 结构不识：标「待确认（比例未取到）」，不崩，不静默给 0。
- 认定文件字段缺失：对应门槛标待确认。
- **P3 任何失败都不得影响 P1/P2 已有输出**（沿用 P2 的 `score_error` 兜底模式）。

1. `catalog.py`：用真实分类表 .xls 验证白名单分段解析（国A / 省A 名单 + 描述规则抽取）；伪造最小工作簿覆盖缺列 / 空表报错。
2. `level.py`：白名单命中（全国大学生数学建模 → 国A）、描述性命中（五一数模 → 省B）、降一级（→ 校C）、歧义待认定、序列比较。
3. `ratio.py`：已知库命中（五一数模 ≤45% 天然过）、联网 fetch（mock URL 解析）、用户填、fetch 失败兜底。
4. `scholarship.py`：4 门槛各分支、奖金（省B 三等 3 人队 = 800 总额）、校C 无奖金、组队系数边界（2/4/5 人）。
5. `pipeline.py` / CLI：不传竞赛参数时 P1/P2 回归不变；五一数模端到端黄金用例（零联网全自动）。
6. `export.py`：P1/P2 sheet 不变，新增 sheet 字段正确。

真实分类表 / 认定文件不进仓库（gitignored 或测试用合成版本）。
